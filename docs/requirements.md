# 요구사항 — 무엇이 되어야 하나

[처음으로](../README.md) · **요구사항** · [설계](design.md) · [작업 순서](tasks.md) · [진행 상황](progress.md) · [작업 지침](../AGENTS.md)

## 1. 목표

흩어져 있는 사진·영상·메모를 **보관함 폴더 하나에 모아 한눈에** 보고 관리한다.

- **피드 뷰**: 트위터처럼 시간순 카드로 빠르게 훑고, 쓰고, 고친다.
- **궤도 뷰**: 흰 공간에 카테고리별 구체가 떠 있는 3D 장면에서 전체 모양을 둘러보고 날아다니며 찾는다.
- **보관함**: 아무 드라이브·위치에 만든 폴더 하나. 폴더째 옮기면 다른 드라이브·기기로 이동과 백업이 끝난다.
- 분위기: 미니멀, 밝은 흰 공간, 색은 카테고리를 구분할 때만, 모든 것이 떠 있는 입체감.

## 2. 사용자와 기기

- 사용자: 본인 1명. 설명서를 읽지 않아도 튜토리얼과 예시만으로 쓸 수 있어야 한다.
- 기기: Windows PC, Android 폰·태블릿, Android 기반 XR 헤드셋(APK 사이드로드, 2D 패널).
- 환경: 오프라인. 인터넷 없이 모든 기능이 동작한다.
- 규모 목표: 보관함 하나에 포스트 2,000개, 첨부 3,000개.

## 3. 핵심 개념

```
보관함 (아무 드라이브·위치의 폴더 하나)
 +-- 카테고리 = 보관함 안의 폴더 (궤도 뷰의 구체 하나)
 |    `-- 포스트 = 마크다운 파일 하나
 |         +-- 메모 텍스트 (첫 줄 = 제목, #태그)
 |         `-- 첨부 0개 이상 (사진·영상, 같은 카테고리의 첨부/ 폴더)
 `-- .az/ = 앱 전용 캐시·설정·휴지통 (지워도 다시 만들어짐)
```

| 용어 | 코드 이름 | 뜻 |
|---|---|---|
| 보관함 | `Vault` | 사용자가 고른 드라이브·위치에 만드는 폴더 하나. 그 안에 모든 기록이 평범한 파일로 들어 있다. Obsidian으로 열어도 읽힌다 |
| 포스트 | `Post` | 기록 한 건 = `.md` 파일 하나. **메모 + 첨부 0개 이상 + 카테고리 1개 + #태그 + 작성 시각**. 메모만 있거나 사진만 있어도 된다. 피드 그리드에는 첨부 4개까지 보이고 나머지는 「+n」 |
| 첨부 | `MediaRef` | 포스트에 붙은 사진·영상 파일. 보관함 기준 상대 경로로 가리킨다 |
| 카테고리 | `Category` | 보관함 바로 아래 폴더. 색을 하나씩 가진다. 폴더 밖(보관함 맨 위)에 있는 포스트는 「미분류」 |
| 태그 | `TagParser` | 메모 안의 `#단어`. 같은 태그를 가진 포스트끼리 궤도 뷰에서 선으로 이어진다 |
| 가져오기 | `ImportJob` | 보관함 밖의 사진·영상을 **복사해서** 보관함에 넣는 것. 원본은 건드리지 않는다 |
| 피드 뷰 | `FeedView` | 시간순 카드 목록 |
| 궤도 뷰 | `OrbitView` | 카테고리별 구체와 링이 떠 있는 3D 공간 |
| 내비게이터 | `NavigatorCard` | 선택한 포스트의 자세한 정보를 보여주는 카드. 두 뷰에서 똑같이 쓴다 |
| 휴지통 | `Trash` | 지운 포스트와 첨부가 가는 `.az/trash/`. 되살릴 수 있다 |
| 최근 보관함 | `VaultCatalog` | 이 기기에서 연 보관함 목록. 보관함 밖, 기기별 설정에 저장 |

## 4. 기능 요구

우선순위: **Must** = 없으면 앱이 아님 · **Should** = 있어야 완성도 · **Could** = 여유가 되면

### Must

| ID | 기능 | 내용 |
|---|---|---|
| F-01 | 포스트 작성 | 텍스트 입력 + 사진·영상 첨부(끌어다 놓기 또는 파일 선택) + 카테고리 선택. `#태그`는 저장할 때 자동 추출. 첨부는 보관함으로 복사 |
| F-02 | 바깥 폴더 가져오기 | 아무 드라이브의 폴더 선택 → 하위 폴더까지 사진·영상을 찾아 **파일 하나당 포스트 1개** 생성. 시작 전에 개수·총 용량·보관함 드라이브의 남은 공간을 보여주고, 모자라면 막는다. 카테고리 기본값은 고른 폴더 이름. 작성 시각은 사진 촬영일(EXIF) → 없으면 파일 수정 시각. **같은 내용의 파일은 건너뜀**. 진행률 표시, 취소 가능, 다음에 이어서 |
| F-03 | 피드 | 최신순 카드 목록(고정 포스트는 맨 위). 카드 = 카테고리 아이콘·이름·상대 시간·즐겨찾기 / 메모(태그 강조) / 미디어 그리드(1장 꽉, 2장 좌우, 3장 1+2, 4장 2×2) / 태그. 스크롤하면 이어서 불러옴 |
| F-04 | 미디어 뷰어 | 사진 크게 보기, 영상 재생·탐색·음량·전체화면. 포스트 안 첨부끼리 `←` `→` 이동, `Esc` 닫기 |
| F-05 | 범례와 유형 필터 | 카테고리 범례(색 점 + 이름 + 개수). 누르면 숨김/표시. 유형 필터: 전체·사진·영상·메모. 두 뷰에 똑같이 적용 |
| F-06 | 보관함 만들기·열기 | **아무 드라이브(C:·D:·외장·네트워크·SD 카드 등)·아무 위치**를 골라 새 보관함 폴더를 만든다(예시 포함 / 빈 보관함). 만들기 전 점검: 쓰기 권한, 남은 공간, 시스템 폴더 금지, 다른 보관함 안 중첩 금지, 네트워크 드라이브 경고. 기존 보관함 열기, 이 기기의 「최근 보관함」 목록(경로가 사라졌으면 다시 찾기·빼기), [보관함 폴더 열기] 버튼 |
| F-07 | 수정·삭제 | 메모 텍스트·카테고리 수정(카테고리를 바꾸면 파일과 첨부를 옮기고 링크를 고침). 포스트 삭제는 확인 후 휴지통으로. 카테고리 추가·이름·색 변경 |
| F-08 | 궤도 뷰 | 3D 공간에 카테고리별 반투명 구체와 궤도 링, 그 안에 포스트 노드. 멀리서는 색 점, 가까이 가면 알약 모양 라벨. 드래그(스와이프) = 회전, 휠(핀치) = 앞뒤 이동, 탭 = 선택(카메라가 날아감), 더블탭 = 전체 보기. 피드 ↔ 궤도 전환 버튼 |
| F-09 | 내비게이터 카드 | 어느 뷰에서든 포스트를 선택하면 카드 표시: 카테고리, 제목, 썸네일, 메모 요약, 시각·태그·연결 수, [파일 열기] [피드에서/궤도에서 보기] [닫기] |
| F-10 | 튜토리얼과 예시 보관함 | 첫 실행 때 「예시 포함」으로 만들면 시작하기 포스트 1개와 예시 포스트 6개(사진 5장·영상 1개)가 들어간 보관함을 만들고 코치마크 7단계를 띄운다. 건너뛸 수 있고 [?]로 다시 본다 |

### Should

| ID | 기능 | 내용 |
|---|---|---|
| F-11 | 검색 | 메모·태그·파일 이름으로 찾기. 피드에서는 목록을 거르고, 궤도 뷰에서는 `Enter`로 첫 결과로 날아감 |
| F-12 | 즐겨찾기·고정 | 포스트에 ☆ 표시, 즐겨찾기만 보기. 고정한 포스트는 피드 맨 위 |
| F-13 | 태그 필터 | 태그를 누르면 그 태그 포스트만 보기 (두 뷰 공통) |
| F-14 | 끊긴 첨부 복구 | 첨부 파일이 없으면 카드·노드에 「파일을 찾을 수 없음」 표시, 다른 파일로 다시 연결 |
| F-15 | 바깥 편집 반영 | 메모장·Obsidian 등에서 `.md`를 고치거나 파일을 옮기면 앱이 감지해 다시 읽는다. 앱에서 고치는 중에 바깥에서도 바뀌었으면 「다시 불러오기 / 덮어쓰기」를 묻는다 |
| F-16 | 궤도 여행 | 궤도 뷰에서 [궤도 여행] → 보이는 포스트를 시간순으로 카메라가 하나씩 날아가며 보여줌. `← 이전` / `다음 →`, 직접 조작하면 멈춤 |
| F-17 | 튜토리얼 체크리스트 | 「A-Z 시작하기.md」의 체크리스트를 사용자가 해당 행동을 하면 앱이 채운다 (파일이 바뀌는 걸 직접 보게) |

## 5. 비기능 요구

| 분류 | 요구 |
|---|---|
| 원본 보호 | 가져올 때 바깥 원본 파일은 읽기만 한다. 수정·이동·삭제하지 않는다 |
| 위치 자유 | 보관함은 사용자가 고른 아무 드라이브·위치에 만든다. 앱 코드에 특정 드라이브·경로를 고정하지 않는다 |
| 이식성 | 보관함 폴더를 다른 드라이브·기기로 복사하면 그대로 열린다. 보관함 안에는 절대 경로를 저장하지 않는다. `.az/`의 캐시가 없어도 다시 만든다 |
| 개방 형식 | 포스트는 YAML 머리말 + 마크다운 + `![[첨부]]`. Obsidian으로 열어도 읽히고, 메모장으로 고쳐도 앱이 반영한다 |
| 자료 안전 | 쓰기는 원자적으로(임시 파일 → 바꾸기). 삭제는 휴지통으로. 저장 중 꺼져도 파일이 깨지지 않는다 |
| 성능 | 포스트 2,000개에서 피드 첫 화면 2초 이내. 궤도 뷰 데스크톱 60fps, 폰·헤드셋 30fps 이상 |
| 반응성 | 가져오기·해시·썸네일 생성 중에도 화면이 멈추지 않는다. 드라이브가 느리거나 분리돼도 앱이 멈추지 않는다 |
| 지원 형식 | 사진: jpg·jpeg·png·gif·webp·bmp(heic는 기기가 지원하면) / 영상: mp4·mov·m4v·webm·mkv·avi (H.264·HEVC·VP9·AV1). 재생할 수 없으면 썸네일과 「기본 앱으로 열기」 |
| 완전 로컬 | 인터넷 없이 모든 기능이 동작한다. release APK에는 INTERNET 권한이 없다. 폰트·예시 자료는 앱에 들어 있다 |
| 플랫폼 | Windows 10/11 x64, Android 10 이상 arm64. XR 헤드셋(Meta Quest, Android XR)에서 2D 패널로 동작하는 것을 목표로 한다 |
| 화면·입력 | 폭 360dp 폰부터 데스크톱까지 반응형(1단·2단·3단). 마우스·터치·XR 컨트롤러 포인터 모두로 쓸 수 있다. 터치 대상 48dp 이상. 한국어 UI |
| 움직임 | 운영체제 「애니메이션 줄이기」 설정을 존중한다 |
| 유지보수성 | 파일마다 맡은 일 하나, 로직은 화면과 분리. 로직 파일은 단위 테스트로 확인한다(목표: 로직 코드 80% 이상 테스트) |
| 재사용성 | 두 뷰가 같은 상태와 공통 화면 조각(내비게이터·범례·검색·컨트롤 막대)을 함께 쓴다. 새 미디어 형식·새 플랫폼은 클래스 하나 추가와 등록 한 줄로 늘린다 |
| 가용성 | 파일 하나가 실패해도 나머지는 계속한다. 캐시가 깨지면 다시 만든다. 썸네일 실패 → 자리표시, 재생 실패 → 기본 앱으로 열기. 가져오기를 취소하거나 앱이 꺼져도 다음에 이어서 한다 |
| 배포 | 서명된 release APK(arm64)를 사이드로드한다. Windows는 실행 폴더를 zip으로 배포한다 |

## 7. 수용 기준

| ID | 확인 내용 | 관련 |
|---|---|---|
| AC-1 | 첫 실행에서 아무 드라이브(예: D:)에 예시 포함 보관함을 만들고, 튜토리얼만 보고 카드 하나를 고칠 수 있다 | F-06, F-10 |
| AC-2 | C:와 D:(또는 외장 드라이브)에 보관함을 하나씩 만들고 오가도 내용이 섞이지 않는다 | F-06 |
| AC-3 | 시스템 폴더나 다른 보관함 안에는 만들 수 없고, 남은 공간이 모자라면 안내한다 | F-06, F-02 |
| AC-4 | 아무 드라이브의 사진·영상 폴더를 가져오면 보관함에 사본이 생기고, 원본의 크기·수정 시각은 그대로다 (큰 영상 1개 포함, 재생·탐색 가능) | F-02, F-04 |
| AC-5 | 같은 폴더를 다시 가져오면 새로 생기는 포스트가 0개다 | F-02 |
| AC-6 | 보관함 폴더를 다른 드라이브로 옮기거나 Windows → Android로 복사해도 포스트·카테고리·즐겨찾기가 그대로 열린다 | F-06, 이식성 |
| AC-7 | 같은 폴더를 Obsidian으로 열면 메모·태그·첨부가 보이고, 메모장으로 고친 내용이 앱에 반영된다 | F-15, 개방 형식 |
| AC-8 | 궤도 뷰에서 카테고리마다 구체가 보이고, 드래그·휠(핀치)·탭·더블탭이 동작한다 | F-08 |
| AC-9 | 두 뷰 어디서 선택해도 같은 내비게이터가 뜨고, 「피드에서 보기」/「궤도에서 보기」로 서로 이동한다 | F-08, F-09 |
