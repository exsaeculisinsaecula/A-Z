## 1. 소개

### 1.1 목적
이 문서는 A-Z가 **무엇을 해야 하는지**를 정한다. 어떻게 만드는지는 [설계](design.md)(AZ-AD), 언제 만드는지는 [작업 순서](tasks.md)(AZ-SDP)가 정한다.
읽는 사람: 프로젝트 소유자, 개발에 참여하는 사람, AI 코딩 도구.

### 1.2 범위
A-Z는 사진·영상·메모를 **보관함 폴더 하나**에 모아 피드와 3D 궤도 공간으로 보여주는 로컬 앱이다.

- 하는 것: 보관함 만들기·열기, 포스트 작성·수정·삭제, 바깥 폴더 가져오기, 피드 뷰, 궤도 뷰, 검색·필터, 튜토리얼.
- 하지 않는 것(범위 밖): 클라우드 동기화(폴더 복사나 외부 동기화 도구로 대신) · 여러 사용자 · SNS 업로드 · 사진·영상 편집 · iOS·macOS · 몰입형 XR(공간 속 3D 모드) · AI 분류 · Play 스토어 배포.

### 1.3 제품 개요

#### 1.3.1 제품 관점
```
            +------------------+
  user ---->|       A-Z        |----> OS file manager / default apps   (파일·폴더 열기)
            |  (Windows app,   |
            |   Android APK)   |<---> file system: any volume          (보관함 폴더)
            +------------------+            ^
                                            |
               other apps: Obsidian, text editor, sync tools           (같은 보관함을 읽고 씀)
```
A-Z는 혼자 동작하는 앱이다. 네트워크와 통신하지 않는다. 다른 앱과는 **보관함 폴더(파일)**로만 만난다.

#### 1.3.2 제품 기능 요약

```
A-Z
 +-- 보관함 ....... 아무 드라이브·위치에 만들기, 열기, 최근 목록           (F-06)
 +-- 기록 ......... 작성, 수정, 삭제(휴지통), 카테고리, 즐겨찾기·고정      (F-01, F-07, F-12)
 +-- 가져오기 ..... 바깥 폴더의 사진·영상을 사본으로                        (F-02)
 +-- 보기 ......... 피드, 뷰어, 궤도 뷰, 내비게이터, 궤도 여행              (F-03, F-04, F-08, F-09, F-16)
 +-- 찾기 ......... 범례·유형 필터, 검색, 태그 필터                         (F-05, F-11, F-13)
 +-- 바깥과 함께 .. 끊긴 첨부 복구, 바깥 편집 반영                          (F-14, F-15)
 `-- 익히기 ....... 예시 보관함, 튜토리얼, 체크리스트                       (F-10, F-17)
```

### 1.4 용어 정의
용어는 ISO/IEC/IEEE 24765를 따르되, 이 앱에만 있는 말은 아래처럼 정한다.

| 용어 | 코드 이름 | 정의 |
|---|---|---|
| 보관함 | `Vault` | 사용자가 고른 아무 드라이브·위치의 폴더 하나. 모든 기록이 평범한 파일로 들어 있다 |
| 포스트 | `Post` | 기록 한 건 = `.md` 파일 하나. 메모 + 첨부 0개 이상 + 카테고리 1개 + 태그 + 작성 시각 |
| 첨부 | `MediaRef` | 포스트에 붙은 사진·영상. 보관함 기준 상대 경로로 가리킨다 |
| 카테고리 | `Category` | 보관함 바로 아래 폴더. 색을 하나씩 가진다. 보관함 맨 위의 포스트는 「미분류」 |
| 태그 | `TagParser` | 메모 안의 `#단어` |
| 가져오기 | `ImportJob` | 보관함 밖의 사진·영상을 복사해서 보관함에 넣는 것 |
| 피드 뷰 | `FeedView` | 시간순 카드 목록 |
| 궤도 뷰 | `OrbitView` | 카테고리별 구체와 링이 떠 있는 3D 공간 |
| 내비게이터 | `NavigatorCard` | 선택한 포스트의 상세 카드. 두 뷰가 함께 쓴다 |
| 휴지통 | `Trash` | 지운 포스트·첨부가 가는 `.az/trash/` |
| 최근 보관함 | `VaultCatalog` | 이 기기에서 연 보관함 목록. 보관함 밖에 저장 |
| 볼륨 | `StorageVolume` | 드라이브 하나(로컬·이동식·네트워크·내부 저장소·SD 카드·USB) |
| 검증 (verification) | — | 요구대로 만들었는지 확인 (ISO/IEC/IEEE 24765) |
| 확인 (validation) | — | 사용자에게 맞는 것을 만들었는지 확인 (ISO/IEC/IEEE 24765) |

### 1.5 요구 문장 규칙
- 의무 표현은 ISO/IEC Directives Part 2를 따른다: **해야 한다**(요구) · **하는 것이 좋다**(권고) · **해도 된다**(허용) · **할 수 있다**(가능).
- 요구 하나에 「해야 한다」 하나(단일성). 주어는 「시스템」이다.
- 우선순위는 MoSCoW 기호로 적는다: **M** 필수 · **S** 중요 · **C** 선택. 우선순위와 의무 표현은 별개다(우선순위가 S·C인 요구도 구현한다면 문장대로 해야 한다).
- 검증 방법은 ISO/IEC/IEEE 29148의 네 가지다: **T** 시험 · **D** 시연 · **I** 검토 · **A** 분석.
- 수치와 단위 사이는 한 칸 띄운다(ISO 80000-1). 저장 용량은 SI 접두어(1 MB = 10^6 B), 2의 거듭제곱은 이진 접두어(1 MiB = 2^20 B, IEC 80000-13). 날짜·시각은 ISO 8601.
- ID는 다시 매기지 않는다. 없애는 요구는 「(폐기)」로 남긴다.

### 3.2 기능 요구

각 기능 그룹(F-xx) 아래에 단일 요구(F-xx.y)를 둔다. 수용 기준은 4.2절.

#### F-01 포스트 작성 (M)
| ID | 요구 | 검증 |
|---|---|---|
| F-01.1 | 시스템은 텍스트, 사진·영상 첨부 0개 이상, 카테고리 하나로 포스트를 만들 수 있어야 한다 | T |
| F-01.2 | 시스템은 Windows에서 파일을 작성칸에 끌어다 놓아 첨부할 수 있어야 한다 | D |
| F-01.3 | 시스템은 저장할 때 본문의 `#태그`를 추출해야 한다(코드 블록과 마크다운 제목 표시는 제외) | T |
| F-01.4 | 시스템은 첨부를 보관함의 `<카테고리>/첨부/`로 복사해야 하며 원본을 수정하지 않아야 한다 | T |
| F-01.5 | 시스템은 포스트를 design.md 4.1 형식의 `.md` 파일 하나로 저장해야 한다 | T |
